## Security advisory: the read-only boundary in 2.0.0

**Affected:** `agensgraph-python` 2.0.0, on every AgensGraph release, wherever text someone else
wrote -- a language model's answer, most often -- runs inside `read_only_transaction()`. That
includes the integrations built on it: `langchain-agensgraph` 0.3.1's Cypher QA chain,
`llama-index-agensgraph`, `lightrag-agensgraph`, `cognee-agensgraph` and the `mcp-agensgraph-*`
servers.

**What happened:** inside the block, text sent with no parameters went over PostgreSQL's simple query
protocol, which runs every statement in a string. So `MATCH (n) RETURN n; COMMIT; DROP GRAPH g
CASCADE` ended the read-only transaction and ran the rest with full write access.

**Fixed in 2.1:** every statement inside the block goes over the extended protocol, which takes one
statement and refuses the rest (`42601`); text that would end or split the transaction is refused
before it is sent; the transaction is pinned read-only before its first statement; and this holds on
every route a statement can take -- `execute`, `execute_query`, a cursor, `executemany`, `COPY`,
`stream` and a pipeline.

**Also on AgensGraph 2.14 and 2.15:** those releases run a Cypher write inside a read-only
transaction, and do not check it against privileges -- a role allowed only `SELECT` committed a `SET`
and a `DETACH DELETE`. The fix is in AgensGraph 2.16.0 and was not backported. On those releases 2.1
refuses a statement holding a Cypher write clause before sending it, and a write the reading misses
is undone by the rollback. For model output, prefer the new `run_untrusted()`, which also requires
a role that cannot write.

**To upgrade:** the integrations above ask for `agensgraph-python>=2.0.0`, so upgrading the driver
underneath them is enough:

```console
pip install -U agensgraph-python                 # pip
uv lock --upgrade-package agensgraph-python      # a uv project, then uv sync
poetry update agensgraph-python                  # a Poetry project
```

An installation locked to 2.0.0 stays affected until its lock is updated.

## What else is new

- **AgensGraph 2.14 to 2.18.** What differs between releases is one table,
  `agensgraph.capabilities.FEATURES`, and every release from 2.14.1 to 2.18.6.1 has the whole suite
  run against it on every change.
- **`run_untrusted()`** runs one model-written statement: checked before it is sent, read-only,
  always rolled back, row-capped, under a timeout, as a role that cannot write, in one round trip.
- **`VectorStorage`** chooses where a label's vectors live: in the vertices' properties, the default
  and 2.0.0's design (AgensGraph 2.17 and later), or in a table of their own (every release, and the
  faster one for filtered search). Either is set up, written, searched and dropped the same way.
- **A deadline the client holds too.** A stalled network ends a call within half a second of the
  server's own limit, where 2.0.0 waited indefinitely; nothing but a stalled network does.
- Settings sent with the statement they are for, `run_transaction` with commit resolution, bulk
  writes that return identities, vector types in every format, and spans for COPY, pipelines,
  streams and pool waits.

## Compatible with 2.0.0, except

- psycopg 3.3.6 or later is required, up from 3.3.4.
- `vector_search_options(local=True)` in autocommit, outside a transaction, did nothing; it now
  warns that it does nothing. 3.0 will raise.
- A short deadline is no longer refused, and its server limit sits a little closer to the budget.
- `StaleLabelCache` is classified `REFRESH_LABELS` rather than `RESET_STATE`.
- A statement's span is named for its operation rather than `query`.

The full list is in [CHANGELOG.md](https://github.com/skaiworldwide-oss/agensgraph-python/blob/master/CHANGELOG.md).
